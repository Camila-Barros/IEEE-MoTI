## Overview

This repository contains the implementation and experimental setup of the MoTI solution (MQTT-oriented Things Interoperability), designed to enable communication interoperability among industrial IoT devices across heterogeneous environments.

MoTI provides a modular and scalable architecture based on MQTT, supporting multiple Quality of Service (QoS) levels and secure communication through TLS with client authentication.

The solution enables multiple stakeholders, including companies, institutions, and service providers, to securely access data generated by industrial IoT devices. It is compatible with legacy systems and integrates decentralized storage using IPFS, ensuring distributed data persistence and controlled access beyond local network boundaries.

Critical messages, transmitted with QoS level 2, are prioritized and authenticated through SHA-256 hashing to guarantee data integrity.

---

## Architecture

The MoTI architecture is composed of the following main components:

- MQTT Broker with TLS authentication  
- IoT publishers (industrial device simulators)  
- Subscribers for data processing and forwarding  
- Integration with IPFS for distributed storage  
- External services for data visualization and analysis

## Key Features

- Interoperability across heterogeneous IoT environments  
- Secure communication using TLS with mutual authentication  
- Support for MQTT QoS levels 0, 1, and 2  
- Distributed data storage using IPFS  
- Data integrity verification using SHA-256 hashing  
- Modular and extensible architecture

## Repository Structure

- `publish_to_mosquitto.py` → MQTT publisher (IoT device simulator)  
- `subscribe_to_IPFS.py` → subscriber for cloud/IPFS integration  
- `viewer_csv_from_index.py` → data visualization and retrieval  
- `/certs` → example structure for TLS certificates (no private keys included)  
- `/data` → experimental datasets (optional / generated during execution)  

---

## Experimental Evaluation

The architecture was evaluated using Round-Trip Time (RTT) measurements under different QoS levels (0, 1, and 2), with 500 messages per level.

The results demonstrate:

- Stable communication across all QoS levels  
- Expected trade-offs between latency and delivery guarantees  
- Higher reliability in QoS 2 scenarios

## How to Reproduce the Results

1. Configure the MQTT broker with TLS and client authentication  
2. Generate and configure certificates using OpenSSL  
3. Configure the IPFS node (local or remote)  
4. Run the publisher script to simulate IoT data transmission  
5. Run the subscriber script to receive messages and store them in IPFS  
6. Collect RTT logs generated during execution  
7. Perform statistical analysis using the collected dataset  

---

## Dataset

The dataset consists of RTT measurements for QoS levels 0, 1, and 2.

If not provided, the dataset can be generated using the scripts available in this repository following the described workflow.
